# ACT 叠毛巾任务实验记录

本仓库用于记录当前双臂机械臂基于 **ACT（Action Chunking with Transformers）** 完成叠毛巾任务时的实验现象、问题分析与后续优化计划。

## 1. 当前任务

任务目标：双臂机械臂抓取蓝色方巾靠近机器人一侧的两个下角，并完成后续折叠动作。

当前配置：

- 策略：ACT
- 训练数据：约 100 条人类示范
- 任务：双臂叠毛巾
- 当前现象：完整任务成功率较低
- 最常见失败：推理时机械臂无法稳定、精确地抓住蓝色方巾的两个下角
- 当前尝试：调整外部相机视角，将上方视角切换到机器人对面的黑色三脚架位置，测试不同视角对抓角精度的影响

## 2. 当前核心判断

目前最可能的主要瓶颈并不是 ACT 完全不会执行“折叠”动作，而是任务最开始的 **角点感知与精确抓取（corner acquisition）** 没有学稳定。

整个任务可以拆成：

```text
视觉观察
  ↓
识别蓝色方巾两个下角
  ↓
双臂分别接近两个角
  ↓
精确对准并闭合 gripper
  ↓
双角抓取成功
  ↓
后续拉起 / 折叠
```

其中最关键的入口是：

> 两个 gripper 是否能够分别准确定位并抓住蓝色方巾的两个下角。

如果角点抓取失败，那么后面的折叠轨迹即使已经被 ACT 学会，也无法继续成功执行。

## 3. 为什么 100 条数据可能仍然不够稳定

ACT 的端到端学习形式可以近似理解为：

```text
图像 + 机器人状态
        ↓
      ACT
        ↓
未来一段动作序列
```

对于抓瓶子、抓盒子等容错较大的任务，末端偏差 1–2 cm 仍可能完成抓取。

但抓毛巾角属于非常典型的精细操作：

- 布料柔软且会产生褶皱
- 角点外观并不稳定
- 蓝色方巾下方还有白色毛巾，边界可能不够显著
- gripper 接近时会遮挡目标区域
- 抓取成功对末端位置误差非常敏感

因此 ACT 不仅需要理解“去抓毛巾”，还必须学到十分精确的局部几何信息：

> 角点到底在哪里，以及 gripper 相对于角点的位置关系。

当前数据量下，模型可能已经学到大致动作语义，但还没有形成稳定的角点几何表征。

## 4. 首要实验：相机视角消融

当前正在尝试将外部相机从原先的较高位置调整到机器人对面的黑色三脚架位置。

这个实验不应只理解为“换个相机试试”，而应该明确成：

> **不同视觉视角是否能够提高 ACT 对 deformable-object corner 的定位精度？**

建议固定其他变量，只改变相机视角进行对比。

### 实验 A：原视角

作为 baseline，记录：

- 左 gripper 抓左角成功率
- 右 gripper 抓右角成功率
- 双角同时抓取成功率
- 完整折叠成功率

### 实验 B：对面三脚架视角

保持：

- 相同机器人
- 相同 ACT 训练配置
- 相同任务
- 尽量接近的数据量

仅改变外部相机视角，比较角点定位和抓取成功率。

### 实验 C：双视角

后续可测试：

- 全局相机负责识别整块毛巾的形状和大致角点位置
- 斜视角 / 末端相机负责最后数厘米的精定位

形成：

```text
Global perception
      ↓
粗定位毛巾角
      ↓
接近目标
      ↓
Local perception
      ↓
精确抓角
```

## 5. 不要只统计完整任务成功率

完整任务成功率会把多个失败原因混在一起。

建议把成功概率拆分：

```text
P(完整成功)
=
P(双角抓取成功)
×
P(折叠成功 | 已经抓住双角)
```

每次推理建议记录以下阶段：

| 指标 | 说明 |
|---|---|
| 左臂到达左角 | 左 gripper 是否进入目标角附近 |
| 右臂到达右角 | 右 gripper 是否进入目标角附近 |
| 左角夹持成功 | 是否真正夹住布角 |
| 右角夹持成功 | 是否真正夹住布角 |
| 双角同时成功 | 两侧是否同时稳定夹持 |
| 后续折叠成功 | 已抓住双角后是否完成任务 |

这样能够区分：

1. 视觉角点定位失败
2. 轨迹接近失败
3. gripper 闭合时机错误
4. 双臂协调失败
5. 后续 folding policy 失败

## 6. 建议增加“角点误差”指标

相比单纯统计成功 / 失败，更建议记录 gripper 闭合瞬间到真实角点的距离：

```text
E_corner = || gripper_center - towel_corner ||
```

分别记录左右两侧：

```text
E_left
E_right
```

可以得到类似：

| 方法 | 左角误差 | 右角误差 | 双角抓取成功率 |
|---|---:|---:|---:|
| 原相机 | - | - | - |
| 对面视角 | - | - | - |
| 双视角 | - | - | - |

这个指标能直接回答：

> 新的相机视角究竟有没有让模型更准确地找到毛巾角。

## 7. 一个低成本诊断实验：角点 Marker

可以暂时在蓝色方巾的两个目标角附近增加明显视觉标记，只用于诊断。

目的不是最终依赖 Marker，而是验证：

> 当前失败是否主要来自视觉角点识别困难。

如果相同 ACT 设置下：

```text
无 Marker：成功率低
有 Marker：成功率明显上升
```

则可以较强地说明主要瓶颈来自视觉表征，而不是后续双臂轨迹或折叠动作本身。

## 8. 单独训练“抓两个角”的简化任务

建议将完整任务暂时截断，只训练：

```text
初始状态
  ↓
寻找两个下角
  ↓
双臂接近
  ↓
闭合 gripper
  ↓
双角抓取成功
  ↓
结束
```

暂时不执行后续折叠。

如果：

- 完整 folding task 成功率很低
- 但 grasp-two-corners task 成功率明显更高

则说明：

1. ACT 并不是完全无法学习该任务；
2. 长时序任务可能稀释了最关键的精细抓取监督；
3. 后续可以考虑分阶段训练或层级策略。

## 9. ACT Action Chunk 长度实验

ACT 会一次预测未来一段动作序列。

对于粗粒度 manipulation，这能让动作更加平滑；但抓毛巾角需要较强的闭环视觉修正。

需要重点观察：

> 当 gripper 已经明显偏离角点时，机器人是否仍然继续沿原轨迹执行，而没有及时根据新图像纠正。

如果存在这种现象，可以测试更短的 action chunk，例如：

```text
chunk_size: 100 → 50 → 25 → 10
```

具体最优值需要通过实验决定，而不是预设越短越好。

核心假设：

> 更高频的视觉反馈可能提升最后几厘米的角点对准能力。

## 10. 后续算法方向：显式 Corner Supervision

如果确认角点感知是主要瓶颈，可以考虑不再完全依赖 ACT 从动作监督中隐式学习角点，而是增加一个辅助角点预测任务。

例如：

```text
RGB image
    ↓
Visual Encoder
    ├────────→ ACT action head
    │
    └────────→ Corner prediction head
                 ↓
            left / right corner
```

可以使用坐标预测：

```text
p_left  = (x_left, y_left)
p_right = (x_right, y_right)
```

总损失：

```text
L = L_ACT + λ L_corner
```

也可以进一步使用 heatmap keypoint detection，在真实角点附近生成 Gaussian heatmap，让视觉 backbone 被显式训练去识别布料角点。

## 11. 当前实验优先级

推荐按照低成本、强诊断性的顺序推进：

1. 原相机 baseline
2. 对面三脚架视角
3. 新视角 + 角点 Marker
4. 新视角 + shorter action chunk
5. 单独训练 grasp-two-corners
6. 双视角融合
7. 如果确认感知瓶颈，再考虑增加 corner auxiliary head / heatmap supervision

不建议在问题尚未定位前直接从 100 条数据扩充到数百条数据，因为如果视觉视角或任务表征本身存在瓶颈，大规模补采数据可能只能降低部分随机误差，却不能解决根本问题。

## 12. 当前核心研究问题

目前可以把实验问题明确表述为：

> **在基于 ACT 的双臂布料操作中，任务失败是否主要由 deformable-object corner 的视觉定位误差造成？不同相机视角、视觉显著性和闭环动作频率能否显著提高双角抓取精度与最终折叠成功率？**

这个问题比单纯“提高叠毛巾成功率”更容易设计实验、分析失败模式，也更容易得到可解释的实验结论。
